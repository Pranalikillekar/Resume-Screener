Pick: AI-Powered Resume Screener & Job-Fit Matcher

Reasoning: it's genuinely in-demand right now (AI recruiting/ATS tools are one of the fastest-growing enterprise AI categories), and it fills a gap your churn project doesn't cover — churn is structured/tabular ML, this one shows NLP + text processing, so together they demonstrate real range on a resume. It also reuses your existing stack (Flask, scikit-learn, SQLite), so there's no new framework to learn.

MVP definition

Input: one job description (pasted or uploaded) + a batch of resumes (PDF/text)
Output: a ranked table of resumes scored by fit against the JD, with the matched keywords/skills shown for each
Core method (v1, no paid APIs needed): TF‑IDF vectorization + cosine similarity between JD and resume text — free, runs fully locally, and is easy to explain in an interview before you ever touch embeddings
Explainability: show which skills/keywords from the JD were found in each resume (this is what actually impresses reviewers — not just a black-box score)
Fairness angle: strip name/gender-coded terms before scoring — a genuine differentiator this niche is known for, and cheap to add

Explicitly out of scope for MVP (later phases, once v1 works end-to-end):

Sentence-embedding models (sentence-transformers) instead of TF-IDF
Structured resume parsing (name/years-experience/education extraction via NER)
Bias-audit dashboard
Login/multi-user, cloud deployment

Stack (all free): Python, Flask, scikit-learn (TfidfVectorizer, cosine_similarity), SQLite, pdfplumber for PDF text extraction, pandas. Config values (upload folder, DB path, similarity threshold, stopword list) go in one config.py rather than hard-coded — same pattern as the churn project.

Suggested phases

Project setup + resume/JD ingestion pipeline (parse PDFs → clean text → store in SQLite)
Scoring engine (TF-IDF + cosine similarity, ranked output)
Flask app (upload JD + resumes, view ranked results table)
Explainability layer (matched-keyword highlighting) + name/gender-term stripping
(Stretch) swap TF-IDF for a free local embedding model to improve match quality

One deliberate design choice worth knowing: each screening run scores only the resumes you upload in that request — not every resume ever saved to the database. So the sample resumes from Phase 1 won't quietly show up mixed into your web results; they're still saved to the DB as a record, just not re-scored automatically.

To run it (PowerShell, venv active):

powershell
pip install -r requirements.txt
python app.py

Then open http://127.0.0.1:5000 in your browser, paste in a job description (the sample in data/job_description.txt works), upload the two sample resumes from data/resumes/, and you should see them ranked with matched keywords.

Phase 4

Phase 4 is done — one new file plus targeted edits, all below.

What's new:

fairness.py — two redaction steps: redact_name_line() blanks out the first non-empty line (a simple heuristic, since most resumes put the candidate's name there — our own sample resumes do exactly this), and redact_gendered_terms() replaces honorifics/pronouns/identity words from a config-driven list with [REDACTED], using word-boundary matching so it doesn't mangle words like "herbal"
config.py — added GENDERED_TERMS, the word list fairness.py redacts
scoring.py — the only file that needed to change to wire this in: resumes are anonymized before they're vectorized and scored, and matched keywords are now checked against that same anonymized text so what's shown stays consistent with what was actually scored
results.html / style.css — a visible fairness note explaining the redaction, plus matched keywords now render as chips instead of a plain comma list

Because the anonymization step lives entirely inside scoring.py, neither app.py (Phase 3) nor rank.py (Phase 2) needed any changes — they both just call score_resumes() and get the fairer results automatically.

One honest limitation worth knowing for an interview: the name redaction is a heuristic (first line = name), not true NER — it'll miss resumes formatted differently. Good v2 upgrade path, not a Phase 4 blocker.

To try it: rerun python app.py, upload the sample resumes again — you should see the fairness note on the results page, and the ranking/matched-keywords should look basically identical to before (since "Aditi Rao" and "Rohit Menon" carried no scoring signal anyway), which is itself a nice thing to point out: removing identity information didn't hurt match quality.
